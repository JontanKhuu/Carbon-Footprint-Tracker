## Task: Added Rate Limiting (Part 14)

### What I Did:
Implemented rate limiting for the API using Flask-Limiter to protect against abuse and ensure fair usage. Added stricter limits for authentication endpoints (login/registration) and moderate limits for general API endpoints.

### Step-by-Step Implementation:

#### 1. Added Flask-Limiter Dependency
- **File modified:** `backend/requirements.txt`
- **Added:** `Flask-Limiter==3.8.0`
- **Reason:** Flask-Limiter is a popular and well-maintained rate limiting library for Flask

#### 2. Added Rate Limiting Configuration
- **File modified:** `backend/config.py`
- **Added configuration options:**
  - `RATELIMIT_STORAGE_URL` - Optional Redis URL for distributed rate limiting (for production)
  - `RATELIMIT_ENABLED` - Enable/disable rate limiting (default: true)
- **Reason:** Allows configuration of rate limiting behavior per environment

#### 3. Initialized Flask-Limiter in App Factory
- **File modified:** `backend/app/__init__.py`
- **Changes:**
  - Imported `Limiter` and `get_remote_address` from Flask-Limiter
  - Created limiter instance with default limit of "100 per hour"
  - Enabled rate limit headers in responses (`headers_enabled=True`)
  - Initialized limiter with app, with optional Redis storage support
  - Applied rate limiting to login and registration endpoints (5 per minute)

#### 4. Applied Rate Limits to Authentication Endpoints
- **File modified:** `backend/app/routes/users.py`
- **Changes:**
  - Added `apply_rate_limit()` decorator factory to mark functions for rate limiting
  - Applied `@apply_rate_limit("5 per minute")` to `create_user()` (registration)
  - Applied `@apply_rate_limit("5 per minute")` to `login()` endpoint
- **Reason:** Authentication endpoints are more vulnerable to brute force attacks, so stricter limits are needed

#### 5. Applied Rate Limits in App Factory
- **File modified:** `backend/app/__init__.py`
- **Changes:**
  - After blueprints are registered, scan for functions with `_rate_limit` attribute
  - Apply Flask-Limiter's `limit()` decorator to those functions
  - This allows rate limiting to work with blueprints without circular imports

#### 6. Added Rate Limit Error Handler
- **File modified:** `backend/app/__init__.py`
- **Added:** Custom 429 error handler that returns JSON error response
- **Features:**
  - Returns clear error message: "Rate limit exceeded. Please try again later."
  - Includes error code: "RATE_LIMIT_EXCEEDED"
  - Returns 429 status code (Too Many Requests)
- **Reason:** Provides user-friendly error messages when rate limits are exceeded

### Key Features:

**Rate Limit Configuration:**
- **Login/Registration:** 5 requests per minute (stricter to prevent brute force)
- **General API Endpoints:** 100 requests per hour (moderate limit for normal usage)
- **Rate limiting by IP address:** Uses `get_remote_address` to identify clients
- **Configurable storage:** Supports in-memory (default) or Redis (for production/distributed systems)

**Rate Limit Headers:**
- `X-RateLimit-Limit` - Maximum number of requests allowed
- `X-RateLimit-Remaining` - Number of requests remaining in current window
- `X-RateLimit-Reset` - Time when the rate limit resets
- Headers are automatically included in all responses when rate limiting is enabled

**Error Handling:**
- Custom 429 error handler returns JSON response
- Clear error message for users
- Error code for programmatic handling
- Graceful degradation (rate limiting can be disabled via config)

### Technical Details:

**Flask-Limiter Configuration:**
- **Storage:** In-memory by default (suitable for single-server deployments)
- **Redis Support:** Can be configured via `RATELIMIT_STORAGE_URL` for distributed systems
- **Strategy:** Fixed-window (simpler, predictable behavior)
- **Key Function:** `get_remote_address` (identifies clients by IP address)

**Rate Limit Application:**
- Uses decorator pattern with `apply_rate_limit()` helper
- Rate limits are applied after blueprints are registered
- Functions marked with `@apply_rate_limit()` get rate limiting applied in app factory
- This avoids circular import issues while maintaining clean code

**Default Limits:**
- Global default: 100 requests per hour (applies to all endpoints)
- Login endpoint: 5 requests per minute (overrides default)
- Registration endpoint: 5 requests per minute (overrides default)
- Other endpoints: 100 requests per hour (use default)

**Error Handling:**
- Flask-Limiter automatically raises 429 errors when limits are exceeded
- Custom error handler catches these and returns JSON response
- Error handler is registered with `@app.errorhandler(429)`

**Production Considerations:**
- For production with multiple servers, configure Redis storage:
  - Set `RATELIMIT_STORAGE_URL=redis://localhost:6379/0` in environment
  - This ensures rate limits are shared across all server instances
- Rate limits are per IP address, so users behind NAT/proxy may share limits
- Consider using user ID instead of IP for authenticated endpoints (future enhancement)
